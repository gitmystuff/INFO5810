Querying DBpedia with SPARQL

Wikipedia as a knowledge graph — exploring RDF triples from the world's largest encyclopedia.
INFO 5810

1

Open the DBpedia SPARQL Explorer

Navigate to dbpedia.org/snorql — this is DBpedia's built-in query interface. You'll see a large text area and a green "Go" button.

Endpoint URL
https://dbpedia.org/snorql/
If the interface is slow, try the mirror at live.dbpedia.org/snorql/

DBpedia is the RDF version of Wikipedia. Every Wikipedia article becomes a resource with a URI. Every infobox field becomes a predicate. The field's value becomes the object. The result is billions of RDF triples connecting people, places, events, and concepts.

2

Paste and read the ship query

Clear the default query and paste the query below. Don't run it yet — read it together first.

# Find ships operated by White Star Line with their tonnage
SELECT ?ship ?shipLabel ?tonnage
WHERE {
  ?ship a dbo:Ship ;
        dbo:operator dbr:White_Star_Line ;
        rdfs:label ?shipLabel ;
        dbo:grossTonnage ?tonnage .
  FILTER(lang(?shipLabel) = "en")
}
ORDER BY DESC(?tonnage)
SELECT ?ship ?shipLabel ?tonnage
WHERE {
  ?ship a dbo:Ship ;
        dbo:operator dbr:White_Star_Line ;
        dbo:grossTonnage ?tonnage
}
▸ ?ship — an unbound variable; SPARQL will find all values that fit the pattern
▸ a dbo:Ship — shorthand for rdf:type dbo:Ship; filters to resources typed as ships in the DBpedia Ontology
▸ dbo:operator dbr:White_Star_Line — the resource must have this predicate pointing at this specific entity. dbo: is the DBpedia Ontology namespace; dbr: is the DBpedia resource namespace
▸ Semicolon syntax — the semicolons chain multiple predicate–object pairs onto the same subject (?ship), avoiding repetition
▸ FILTER(lang(?shipLabel) = "en") — Wikipedia stores labels in every language; we keep only English ones
3

Run the query and read the results

Click Go. The results table lists ships, their English labels, and gross tonnage in tons, sorted largest-first.

Instructor note: The Titanic (RMS Titanic) should appear — this is the same data used in the slide 13 example. Pointing out a ship students recognize anchors the abstract triples to something concrete.

Notice the value in the ?ship column — it looks like:

http://dbpedia.org/resource/RMS_Olympic

That is a URI. It is the ship's unique identifier in the Linked Data web — the same URI an application in Tokyo, a researcher in Berlin, and our SPARQL query all use to refer to the same concept. This is the "Linked" in Linked Data.

4

Follow a URI — explore a resource page

Click one of the URIs in the ?ship column. Your browser navigates to that resource's DBpedia page — a structured view of every triple where that ship is the subject.

Example resource page
http://dbpedia.org/resource/RMS_Titanic
Scroll down — you'll see properties grouped by ontology: dbo: (structured), dbp: (raw Wikipedia infobox), owl:sameAs links to Wikidata and other datasets

Point out the owl:sameAs section at the bottom. That link connects this DBpedia resource to the equivalent Wikidata item (wd:Q25150). This is how knowledge graphs federate: different databases, one web of facts.

dbo:displacement dbo:length dbo:speedKnots dbo:builder owl:sameAs
5

Simplify — a two-triple query

Back in snorql, paste this simpler query that shows how little code is needed to get meaningful results:

# Famous scientists born in Germany
SELECT ?person ?name ?birthDate
WHERE {
  ?person a dbo:Scientist ;
          dbo:birthPlace dbr:Germany ;
          rdfs:label ?name ;
          dbo:birthDate ?birthDate .
  FILTER(lang(?name) = "en")
}
ORDER BY ?birthDate
LIMIT 20

Run it. Note that we added LIMIT 20 — DBpedia has no built-in result cap, so always limit your queries while exploring or you may wait a long time for thousands of rows.

The pattern is the same as Wikidata — SELECT variables, WHERE with triple patterns, FILTER for language, ORDER BY to sort. The only difference is the vocabulary: dbo: instead of wdt:, resource URIs instead of Q-numbers.
Part 2

On Your Own — Explore DBpedia

6

Find what properties are available for a type

Before you can write your own query, you need to know what predicates exist. This query lists every property used by DBpedia resources of type dbo:Scientist:

# Discover all predicates on Scientist resources (sample of 50)
SELECT DISTINCT ?predicate
WHERE {
  ?person a dbo:Scientist ;
          ?predicate ?value .
}
LIMIT 50

Browse the results. You'll see predicates like dbo:field, dbo:award, dbo:almaMater, dbo:knownFor. Pick one that interests you for Step 7.

Try swapping the type: Replace dbo:Scientist with dbo:Film, dbo:City, or dbo:Band to discover the properties for those types.
7

Write your own 2–3 triple query

Choose any topic you like. Write a SPARQL query with at least two triple patterns — a type triple and at least one property triple. Use the template below as a starting point:

SELECT ?thing ?label ?someProperty
WHERE {
  ?thing a            # type (dbo:Film, dbo:City, dbo:Athlete…)
         ?someProperty  # predicate you found in Step 6
         rdfs:label ?label .
  FILTER(lang(?label) = "en")
}
LIMIT 25
Starter ideas: movies with a specific director, athletes from a particular country, universities founded before 1800, Nobel Prize winners in physics.

When your query runs successfully, write down (or screenshot) the SPARQL you wrote and note how many results you got.

8

Bonus — bridge to Wikidata with owl:sameAs

DBpedia resources have owl:sameAs links pointing to their Wikidata equivalents. This federated link connects two entirely separate knowledge graphs:

# Find the Wikidata URI for a DBpedia scientist
SELECT ?person ?name ?wikidataURI
WHERE {
  ?person a dbo:Scientist ;
          rdfs:label ?name ;
          owl:sameAs ?wikidataURI .
  FILTER(lang(?name) = "en")
  FILTER(STRSTARTS(STR(?wikidataURI), "http://www.wikidata.org"))
}
LIMIT 10

The second FILTER keeps only the owl:sameAs links that point to Wikidata (since DBpedia links to many datasets). Copy a Wikidata URI from the result, paste it into a new browser tab, and compare the two pages describing the same person.

Think about it: These two triplestores were built independently — DBpedia by mining Wikipedia infoboxes, Wikidata by human editors. Yet they describe many of the same entities. The owl:sameAs links are what make them one integrated web of knowledge, not two separate islands.
