Querying DBpedia with SPARQL

Wikipedia as a knowledge graph — exploring RDF triples from the world's largest encyclopedia.
INFO 5810

1

Open the DBpedia SPARQL endpoint

Navigate to dbpedia.org/sparql — this is DBpedia's query interface. You'll see a text area for your query and a blue Run Query button.

Endpoint URL
https://dbpedia.org/sparql
Make sure the default graph is set to http://dbpedia.org — it usually is by default.

DBpedia converts Wikipedia infoboxes into RDF triples. Every article becomes a resource with a URI, every infobox field becomes a predicate, and the field's value becomes the object.

2

Paste and read the scientists query

Clear the default query, paste the query below, and read it together before running.

# Scientists — name, birth date, and birth place
SELECT ?person ?name ?birthDate ?birthPlace
WHERE {
  ?person a dbo:Scientist ;
          rdfs:label ?name ;
          dbo:birthDate ?birthDate ;
          dbo:birthPlace ?birthPlace .
  FILTER(lang(?name) = "en")
}
ORDER BY ?birthDate
LIMIT 20
?person a dbo:Scientist ;
        rdfs:label ?name ;
        dbo:birthDate ?birthDate ;
        dbo:birthPlace ?birthPlace .
▸ a dbo:Scientist — shorthand for rdf:type; only resources classified as scientists in the DBpedia Ontology match
▸ rdfs:label ?name — fetches the human-readable name; the FILTER keeps only English labels
▸ dbo:birthDate — a structured date value mapped from the Wikipedia infobox by the DBpedia Ontology
▸ dbo:birthPlace — links to another DBpedia resource (a city, country); the value will be a URI, not a plain string
▸ LIMIT 20 — always use this on DBpedia; unlike Wikidata there is no built-in cap and an unlimited query can run for a very long time
3

Run the query and read the results

Click Run Query. Results show scientists sorted by birth date, oldest first.

Notice that the ?person and ?birthPlace columns both contain URIs — not plain text. A URI like:

http://dbpedia.org/resource/Albert_Einstein

is the scientist's unique identifier in the Linked Data web. The ?birthPlace column shows URIs too — each one is a DBpedia resource for a city or country, itself connected to thousands of other triples.

Key idea: In RDF, everything is a URI or a literal. When an object is a URI it means the value is itself a node in the graph — you can follow it to find more triples.
4

Follow a URI — explore a resource page

Copy one of the URIs from the ?person column and paste it in a new browser tab (or click it if it's a hyperlink). You'll land on that scientist's DBpedia resource page — every triple where they are the subject.

Example resource page
http://dbpedia.org/resource/Albert_Einstein
Scroll down to see dbo: (ontology-mapped) and dbp: (raw infobox) properties, and owl:sameAs links to Wikidata and other datasets.
dbo:field dbo:award dbo:almaMater dbo:knownFor owl:sameAs
5

Filter by birth place

Modify the query to return only scientists born in a specific country by adding one more triple that pins ?birthPlace to a known resource:

# Scientists born in Germany, oldest first
SELECT ?person ?name ?birthDate
WHERE {
  ?person a dbo:Scientist ;
          rdfs:label ?name ;
          dbo:birthDate ?birthDate ;
          dbo:birthPlace dbr:Germany .
  FILTER(lang(?name) = "en")
}
ORDER BY ?birthDate
LIMIT 20
The pattern is the same as Wikidata — SELECT, WHERE with triple patterns, FILTER for language, LIMIT. The vocabulary differs: dbo: instead of wdt:, dbr: resource URIs instead of Q-numbers.
6

Discover what properties exist for a type

Before writing your own query, find out what predicates DBpedia has for the type you want. This query lists every property used on dbo:Scientist resources:

# Discover predicates for a type
SELECT DISTINCT ?predicate
WHERE {
  ?thing a dbo:Scientist ;
         ?predicate ?value .
}
LIMIT 50

Browse the results for predicates like dbo:field, dbo:award, dbo:almaMater. Pick one that interests you.

Try a different type: Replace dbo:Scientist with dbo:Film, dbo:City, dbo:Athlete, or dbo:Band to explore their available properties.
7

Write your own query

Use the working example below as a starting point, then change the type and property to something from Step 6:

# Example: films directed by Christopher Nolan
SELECT ?film ?label ?year
WHERE {
  ?film a dbo:Film ;
        rdfs:label ?label ;
        dbo:director dbr:Christopher_Nolan .
  OPTIONAL { ?film dbo:releaseDate ?year }
  FILTER(lang(?label) = "en")
}
LIMIT 25

Run the example first to confirm it works, then modify it: swap dbo:Film for your chosen type, and swap dbo:director and dbr:Christopher_Nolan for a predicate and value that fits your topic.

Other ideas: athletes from a specific country (dbo:birthPlace dbr:Brazil), universities founded before 1800 (dbo:foundingYear), albums by a band (dbo:artist dbr:The_Beatles).
8

Bonus — bridge to Wikidata with owl:sameAs

DBpedia resources have owl:sameAs links to their Wikidata equivalents, connecting two independently-built knowledge graphs:

# Find Wikidata URIs for DBpedia scientists
SELECT ?person ?name ?wikidataURI
WHERE {
  ?person a dbo:Scientist ;
          rdfs:label ?name ;
          owl:sameAs ?wikidataURI .
  FILTER(lang(?name) = "en")
  FILTER(STRSTARTS(STR(?wikidataURI), "http://www.wikidata.org"))
}
LIMIT 10

Copy a Wikidata URI from the results and open it in a new tab. Compare what DBpedia and Wikidata each say about the same person.

Think about it: DBpedia was built by mining Wikipedia infoboxes; Wikidata was built by human editors. They describe many of the same entities. The owl:sameAs links are what make them one connected web of knowledge rather than two isolated datasets.
